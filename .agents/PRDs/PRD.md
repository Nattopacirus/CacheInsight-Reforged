# เอกสารข้อกำหนดผลิตภัณฑ์ (PRD): CacheInsight-Reforged

## 1. บทสรุปผู้บริหาร (Executive Summary)

**CacheInsight-Reforged** คือการนำแอปพลิเคชันเพื่อการศึกษา Cache Insight เดิมมาสร้างใหม่และปรับปรุงให้ทันสมัย เป้าหมายหลักของโปรเจกต์นี้คือการจำลองการทำงานของ Cache Memory ที่มีประสิทธิภาพและความเสถียรสูง โดยเฉพาะการแก้ไขปัญหาหน้า UI ค้าง (Freezing) ในเวอร์ชัน React เดิม เมื่อต้องประมวลผลชุดข้อมูลขนาดใหญ่ (สูงสุดถึง 1,000,000 Memory Addresses)

ด้วยการย้ายกลไกการจำลอง (Simulation Engine) หลักไปไว้ที่หลังบ้าน (Backend) ซึ่งพัฒนาด้วย Python/FastAPI และใช้การประมวลผลแบบ Background Tasks ทำให้แอปพลิเคชันนี้มีการตอบสนองที่รวดเร็วและไม่บล็อกหน้าจอผู้ใช้ นอกจากนี้ โปรเจกต์นี้ยังเพิ่มคุณค่าในฐานะเครื่องมือทางการศึกษา โดยการแทรกหน้าต่าง Popup สอดแทรกความรู้ที่เขียนด้วย Markdown เพื่ออธิบายทฤษฎี Cache และเทคนิคการ Mapping ผ่านภาพและข้อความ

## 2. ภารกิจหลัก (Mission)

เพื่อจัดหาเครื่องมือจำลอง Cache Memory ที่ทำงานได้อย่างรวดเร็ว เสถียร และสวยงามน่าใช้งาน ให้แก่นักศึกษาวิทยาการคอมพิวเตอร์และผู้สอน เครื่องมือนี้ต้องสามารถรองรับชุดข้อมูลมหาศาลได้ พร้อมทั้งสอนแนวคิดด้านสถาปัตยกรรมคอมพิวเตอร์ที่อยู่เบื้องหลังได้อย่างมีประสิทธิภาพ

**หลักการสำคัญ (Core Principles):**
- **Backend is the Brain:** การคำนวณที่หนักหน่วงทั้งหมด (การแยก Tag/Index/Offset, การคำนวณ Hit/Miss) จะต้องทำงานที่ Backend เพื่อให้ UI ลื่นไหลตลอดเวลา
- **Accuracy First:** ตรรกะการจำลองจะต้องตรงกับ "Ground Truth" ซึ่งอ้างอิงจากโค้ด C++ เดิม (`cachesim.cpp`) อย่างเคร่งครัด
- **Educational Value:** อินเทอร์เฟซต้องไม่เพียงแค่แสดงผลลัพธ์ แต่ยังต้องอธิบายว่า "ทำไม" และ "อย่างไร" ผ่านโมดูลทฤษฎีที่แทรกอยู่
- **Simplicity & Performance:** การประมวลผลพื้นหลัง (Background processing) ต้องมีน้ำหนักเบาแต่มีประสิทธิภาพ โดยใช้ Process Pools สำหรับงาน CPU-bound เพื่อไม่ให้บล็อกการทำงานหลัก (Event loop)

## 3. กลุ่มเป้าหมายผู้ใช้งาน (Target Users)

- **นักศึกษาคณะวิทยาการคอมพิวเตอร์ / วิศวกรรมศาสตร์:** ผู้ที่ต้องการจำลองภาพการทำงานและทำความเข้าใจว่าเทคนิคการทำ Cache Mapping แบบต่างๆ (Direct, Set-Associative, Fully Associative) รวมถึงพารามิเตอร์อื่นๆ (เช่น Cache Size, Block Size) ส่งผลต่ออัตรา Hit/Miss อย่างไร
- **อาจารย์ / ผู้สอน:** ผู้ที่ต้องการเครื่องมือที่เสถียร รองรับข้อมูล Address ได้มหาศาล (สูงสุด 1,000,000 บรรทัด) เพื่อใช้สาธิตประสิทธิภาพการทำงานของ Cache ให้นักศึกษาดูโดยที่แอปไม่ค้างหรือพัง
- **ความรู้ทางเทคนิค:** ระดับปานกลางถึงสูง ผู้ใช้จะมีความเข้าใจพื้นฐานเกี่ยวกับแนวคิดสถาปัตยกรรมคอมพิวเตอร์ (เลขฐานสิบหก, เลขฐานสอง, การทำ Caching)

- [x] รองรับเทคนิค Cache Mapping: Direct Mapped, Set-Associative (n-way), Fully Associative

- [ ] การตั้งค่าสำหรับการ Deploy บน Cloud (ออกแบบมาให้ใช้งานเฉพาะบนเครื่อง Local)

## 5. เรื่องราวของผู้ใช้งาน (User Stories)

1. **ในฐานะนักศึกษา**, ฉันต้องการอัปโหลดไฟล์จำลองข้อมูลขนาดใหญ่ (1,000,000 Address) และมี Progress Bar บอกความคืบหน้า เพื่อที่เบราว์เซอร์ของฉันจะได้ไม่ค้างระหว่างรอผลลัพธ์
2. **ในฐานะนักศึกษา**, ฉันต้องการกดปุ่ม "ข้อมูล (Info)" เพื่ออ่านคำอธิบายในรูปแบบ Markdown สำหรับทฤษฎี Set-Associative Mapping เพื่อที่ฉันจะได้เข้าใจหลักการเบื้องหลังการทำงานนี้
3. **ในฐานะอาจารย์**, ฉันต้องการบันทึกการตั้งค่าของ Cache โดยเฉพาะ (เช่น Cache 32KB, Block 64B, 4-Way) เป็นค่าล่วงหน้า (Preset) เพื่อที่ฉันจะสามารถดึงมาใช้งานระหว่างการสอนได้อย่างรวดเร็วโดยไม่ต้องพิมพ์ใหม่
4. **ในฐานะผู้ใช้**, ฉันต้องการให้ระบบตรวจสอบข้อมูลที่กรอกเข้ามา (รับประกันว่า Size ต่างๆ ต้องเป็น Power of 2) เพื่อที่ฉันจะได้ไม่เผลอรันการจำลองที่ข้อมูลผิดพลาดและทำให้ได้ผลลัพธ์ทางคณิตศาสตร์ที่ไม่ถูกต้อง
5. **ในฐานะผู้ใช้**, ฉันต้องการเรียกดูประวัติงานจำลองผลในอดีต (History) และผลลัพธ์ของมัน เพื่อที่ฉันจะได้นำผลการตั้งค่า Cache ที่ต่างกันมาใช้เปรียบเทียบภายใต้ไฟล์ข้อมูลเดียวกัน

## 6. สถาปัตยกรรมหลักและรูปแบบ (Core Architecture & Patterns)

**สถาปัตยกรรมระดับสูง (High-Level Architecture):**
1. **Frontend (Client):** Next.js คู่กับ Tailwind CSS จัดการหน้าจอผู้ใช้งาน, เรนเดอร์ไฟล์ Markdown, แบบฟอร์ม Preset และการ Polling API เพื่ออัปเดตสถานะงาน
2. **Backend (Simulation Engine):** FastAPI (Python) ให้บริการ REST API สำหรับจัดการ Preset และส่งคิวงาน (Job Submission)
3. **Task Queue:** ใช้งาน `BackgroundTasks` ในตัวของ FastAPI ร่วมกับ `ProcessPoolExecutor` เพื่อใช้ในการคำนวณแบบ Asynchronous ที่ต้องใช้ CPU หนักๆ โดยระบบจะทำการอัปเดตความคืบหน้ากลับไปยังฐานข้อมูลเป็นระยะๆ (เช่น ทุกๆ 10,000 บรรทัด) เพื่อหลีกเลี่ยงปัญหาคอขวดที่ฐานข้อมูล
4. **Database:** Microsoft SQL Server สำหรับเก็บข้อมูล Presets รวมถึงจัดเก็บข้อมูลคิวงานและประวัติงานจำลอง (Simulation Job queue/history tracker)

**หลักการและรูปแบบการออกแบบ (Design Patterns & Principles):**
- **Asynchronous Job Pattern:** Client ส่งไฟล์เข้าเซิร์ฟเวอร์ -> เซิร์ฟเวอร์จะคืนค่า `job_id` กลับทันที -> Client ทำการสร้างลูปตรวจสอบสถานะผ่าน `/jobs/{job_id}/status` จนกว่างานจะเสร็จสิ้น
- **File Handling:** Backend รับไฟล์อัปโหลดแล้วบันทึกลงโฟลเดอร์ชั่วคราว (Temporary directory) ส่งที่อยู่ไฟล์นั้นให้ Background Worker และ Worker ทำการลบไฟล์ทิ้งหลังจากงานจำลองผลเสร็จสมบูรณ์

## 7. เครื่องมือและคุณลักษณะเด่น (Tools/Features)

**กลไกการจำลองการทำงาน (Simulation Engine - Backend):**
- **Validation Engine:** ตรวจสอบความถูกต้องว่าค่าต่างๆ เป็น "Power of 2" ตามเงื่อนไขหรือไม่
- **Parser & Calculator:** ตรวจสอบไฟล์ CSV ทีละบรรทัด, แปลง Hex เป็น Binary, แตกค่า Tag, Index, และ Offset ตามสูตรต่อไปนี้:
  - `Offset Bits = log2(Block Size)`
  - `Index Bits = log2(Number of Sets)` (จำนวน Sets = Cache Size / (Block Size * N-way))
  - `Tag Bits = Total Address Bits - Index Bits - Offset Bits`
- **LRU Cache State Manager:** จำลองสถานะ Hit/Miss ด้วยคิว LRU ประจำแต่ละ Set

**การจัดวางหน้าต่างให้ความรู้ (Educational Layout - Frontend):**
- **Markdown Renderer:** ดึงแพ็กเกจ `react-markdown` มาอ่านไฟล์ `.md` ภายในโฟลเดอร์ `/public` และนำมาแสดงผลเป็น Modal popups พร้อมรูปภาพ

## 8. เทคโนโลยีที่ใช้งาน (Technology Stack)

- **Frontend:** Next.js, React.js, Tailwind CSS, `react-markdown`
- **Backend:** Python 3.10+, FastAPI, Uvicorn, `pandas` (เผื่อเลือก สำหรับการดึงข้อมูล CSV อย่างรวดเร็ว หรือใช้แค่ไลบรารี `csv` มาตรฐานก็พอ), `multiprocessing`
- **Database:** Microsoft SQL Server
- **ORM:** SQLAlchemy (ควบคู่กับ `pyodbc` หรือไดรเวอร์ที่เชื่อมต่อกับ SQL Server ได้)

## 9. ความปลอดภัยและการกำหนดค่า (Security & Configuration)

- **Authentication:** ไม่จำเป็น (ทำงานในระดับ Single-user บนเครื่องตนเอง)
- **Configuration:** เก็บตัวแปรสภาวะแวดล้อมต่างๆ ในไฟล์ (`.env`) เช่น Connection Strings สำหรับต่อ SQL Server และ Port หลังบ้านต่างๆ
- **File Security:** ระบบจะอนุญาตและตรวจสอบให้อัปโหลดเฉพาะไฟล์นามสกุล `.csv` พร้อมควบคุมขนาดไฟล์ให้เหมาะสม (เช่น ไม่เกิน 50MB) เพื่อป้องกันพื้นที่ฮาร์ดดิสก์เต็ม

## 10. สเปกของ API คร่าวๆ (API Specification Draft)

- **`POST /api/presets`**: สร้าง Configuration preset ขึ้นมาใหม่
- **`GET /api/presets`**: เรียกดู Preset ที่มีการบันทึกไว้ทั้งหมด
- **`POST /api/simulate`**: 
  - **Request:** ส่งรูปแบบ `multipart/form-data` ซึ่งบรรจุไฟล์ `.csv` พร้อมด้วย JSON Payload เพื่อตั้งค่าพารามิเตอร์ของ Cache
  - **Response:** `{ "job_id": "uuid-string", "status": "Pending" }`
- **`GET /api/simulate/{job_id}`**: 
  - **Response:** `{ "status": "Processing", "progress": 45, "result": null }`
- **`GET /api/history`**: เรียกดูประวัติคิวงานทั้งหมดและผลลัพธ์การจำลอง

## 13. สิ่งที่ต้องพิจารณาในอนาคต (Future Considerations)

- การเพิ่มนโยบายการแทนที่ข้อมูลแบบใหม่ๆ เช่น FIFO, Random
- รองรับการปรับแต่งความจุและขนาดของหน่วยความจำตามที่ต้องการ (ตอนนี้ล็อกการกำหนดค่าเป็น Byte-addressable ไว้)
- ระบบจำลองการทำงาน Cache แบบเป็นลำดับชั้น (Multi-level cache simulation เช่น L1, L2, L3)

## 14. ความเสี่ยงและแนวทางป้องกัน (Risks & Mitigations)

1. **ความเสี่ยง:** `ProcessPoolExecutor` อาจใช้ RAM หรือ CPU มากเกินไป หากมีการโยนงานสเกลใหญ่เข้าระบบหลายงานพร้อมกัน
   - **แนวทางป้องกัน:** จำกัดพารามิเตอร์ `max_workers` ให้เป็น 1 หรือ 2 ตัว ภายใน `ProcessPoolExecutor` เพื่อให้ระบบนำงานเข้าแถวคอยตามลำดับ ป้องกันไม่ให้คอมพิวเตอร์พังหรือค้าง
2. **ความเสี่ยง:** การดึงข้อมูลไปอัปเดตใน MS SQL Server ทุกๆ บรรทัดจะทำให้ระบบจำลองการทำงานเป็นคอขวด
   - **แนวทางป้องกัน:** สร้างการปรับปรุงแบบรวมยอด (Batch updates) เช่น ให้อัปเดตข้อมูลขึ้น Database ทุกๆ การประมวลผล 10,000 บรรทัด หรืออัปเดตทีละ 1 วินาที
3. **ความเสี่ยง:** ความคลาดเคลื่อนหรือผลลัพธ์ไม่ตรงกันระหว่าง Python Simulation และ Ground Truth (C++)
   - **แนวทางป้องกัน:** เขียน Unit Tests บน Python โดยใช้ `cachesim.cpp` แบบเดิมมาเป็นผู้ชี้ขาดการทดสอบอย่างเคร่งครัด ก่อนเชื่อมกับระบบ API ใดๆ
